# Analogy Bank (ELI5++)

预置类比，用来降低起步成本。**但每一条都必须补上第三列：类比在哪失效。**

这不是可选的形式要求。类比库最大的风险是让人**记住了一个错误的模型**——用户以为懂了，实际记住的是"缓存就是饭盒"，而饭盒不会失效、不会污染、不会把旧饭热给你。ELI5++ 的第一原则是"删掉类比后解释仍成立"，所以类比只能当脚手架，不能当结论。

## 怎么用

1. 选一条类比作为**直觉入口**，不要作为解释本身
2. **必须**把"失效边界"写进产物的 `.boundary` 块
3. 如果找不到诚实的边界，说明这条类比不该用，换一条

## 选比类的判据

好的类比满足三条：

- **结构同构**：类比的部件与概念的部件能一一对上（不是只有"感觉像"）
- **边界可陈述**：你能用一句话说清它在哪失效
- **不引入错误动作**：用户不会因为类比去做一个错误的操作

## 已整理类比（含边界）

| 概念 | 类比 | **类比在哪失效** |
|---|---|---|
| Cache | 饭盒里提前装好饭，饿了不用现做 | 饭盒不会"过期"、不会被别人改、不会和冰箱内容不一致。真实缓存有 TTL、失效、一致性三个饭盒完全没有的问题 |
| Database index | 书前面的目录 | 目录只加速"按关键词找"，不加速"通读全书"。索引对写入是负担，书加目录几乎不花成本 |
| Load balancer | 路口交警分流 | 交警看得见车、能判断哪条道堵。负载均衡器通常只知道计数和健康检查，不知道"这个请求更重" |
| Firewall | 门口保安查名单 | 保安认得人。防火墙按规则匹配包，看不懂"意图"，也拦不住已经进门的人横向移动 |
| DNS | 电话簿，名字换号码 | 电话簿更新慢但确定。DNS 有缓存和多级 TTL，同一个名字在不同机器上可能解析到不同地址 |
| HTTP vs HTTPS | 明信片 vs 密封信 | 密封信只有收件人能拆；HTTPS 还保证"没被改过"（完整性）和"对方确实是它"（身份），这两个明信片/密封信都没覆盖 |
| WebSocket | 打电话，线路一直通 | 电话是独占的。WebSocket 是复用一条 TCP 连接跑多路消息，且中间代理可能随时掐断 |
| Docker / container | 集装箱，货物标准化 | 集装箱不共享内核。容器共享宿主内核，所以"隔离"比虚拟机弱，内核漏洞能穿透 |
| Recursion | 俄罗斯套娃 | 套娃是有限且预先造好的。递归有终止条件和调用栈，栈会溢出，套娃不会 |
| Deadlock | 两人各持对方要的东西，互等 | 这个类比很准，但漏了关键点：死锁需要**四个条件同时成立**，打破任一即可解除。两人互等只是其中一种形态 |
| Race condition | 两个孩子抢最后一块蛋糕，谁快谁赢 | 抢蛋糕的结果是"一个人得到"。竞态的真实危害是**状态被写坏**（两个都以为自己拿到了），不只是输赢不定 |
| Message queue | 餐厅点单排队，厨师按序做 | 排队是严格 FIFO。消息队列常有重投、乱序、重复消费，厨师不会把同一份菜做两次 |
| Git branch | 平行世界 / 分叉的路 | 分支不是"复制整个项目"。Git 分支只是一个指针，成本几乎为零，这点和"分叉路"直觉相反 |
| Encryption | 只有收件人有钥匙的锁箱 | 锁箱不解决"怎么把钥匙给对方"。密钥交换才是难点，类比完全没覆盖 |
| Token (auth) | 一次性门票 | 门票用完就废。Token 通常可重复使用直到过期，且可能被窃取后仍有效——这正是要防范的 |
| Compiler vs interpreter | 翻译整本书 vs 现场口译 | 现代实现是混合的（JIT）。这个二分法本身是简化，别让用户以为只有两种 |
| Async | 点外卖不用守着锅 | 外卖只涉及等待。异步还有回调地狱、竞态、错误传播三个真实难点，类比一个都没有 |
| Regex | 一种描述"长什么样"的暗号 | 暗号是精确匹配。正则的回溯行为可能导致灾难性性能问题，这是它最反直觉的地方 |

## 关于"换一个类比"

如果用户说"没懂""换个说法""这个类比不好"，**不要复用同一结构只换措辞**。换一个**结构不同**的类比，因为同一个结构没讲通，说明映射本身不成立。

**判定"结构不同"**：如果两条类比能共用同一张三列表（部件一一对应），那它们只是换措辞。真正的换结构意味着映射关系变了——比如从"空间包含"换成"时间顺序"。

## 沉淀：把好类比记下来

如果某个类比在实际使用中效果特别好（用户明确说"这个懂了"），可以提议把它追加到本文件的表格里，但要**先问用户**：

- 类比只对当前话题有效，还是可以复用到别处？
- 失效边界写清楚了吗？

不要自动写入。这个文件是共享资产，随手追加会让它变成第二个"没有边界标注"的类比库——那正是要避免的。

## 贡献新类比

新增一条时，三列缺一不可。只有前两列、没有"失效边界"的条目**不要加进来**——那正是这个文件存在的意义。

**关于来源**：社区里存在几十条的类比库（如 kavyabhand/claude-eli5 的 54 条），质量参差且**普遍不标注失效边界**。可以直接借用其中的类比作为灵感，但**必须自己补第三列**再收进来。没有边界的类比不是资产，是负债。

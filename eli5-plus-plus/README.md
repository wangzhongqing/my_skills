# ELI5++

> ELI5 让人听得懂。ELI5+ 让人真正理解。**ELI5++ 让人理解，并且产物是验证过的。**

一个给 AI Agent 用的 skill：把复杂主题解释成一个**自包含、离线可用、经过机械校验**的 HTML 页面。

它不只讲"是什么"，还讲**为什么需要它、怎么工作、什么时候不成立**——并且要求交付前跑完三层校验，不许声称没做过的验证。

```bash
$eli5-plus-plus 用图解解释 RAG
使用 ELI5++ 解释为什么缓存会失效
```

## 它解决什么问题

现有的 ELI5 类 skill 大多只做两件事之一：

- **讲得好** —— 但没有任何校验，产物质量全凭模型自觉
- **能校验** —— 但只管仓库结构，不管生成出来的 HTML 是否真的能看

ELI5++ 要同时做到：**讲得清楚**，并且**产物可验证**。

它针对三个具体失败模式：

| 失败模式 | ELI5++ 的应对 |
|---|---|
| 声称"已验证"，其实没跑 | 第一原则 + 退出码语义（`exit 2` = 没测，不是通过） |
| 类比讲得生动，但让读者记住了错误模型 | 每条类比强制标注"在哪失效" |
| 页面技术上合规，但 JS 一关就看不见 | 动效 opt-in + 专门的正则检查 |

| [DreambigOu/ELI5](https://github.com/DreambigOu/ELI5) | MIT | 受众适配（按身份/用途调语气词汇）、eval 用例的组织方式 | eval 运行器依赖 `claude -p` CLI，换环境就跑不起来 |

所有来源均为 MIT 许可，允许衍生与再分发。

## 功能

### 内容层

- **篇幅三档** —— 简（600–900 字）/ 标准（1200–2000 字，默认）/ 深（2500–4000 字）。篇幅由"读者要拿它做什么"决定，不是默认越短越好
- **事实与类比分离** —— 先列"删掉类比后仍必须为真"的事实清单，类比只当脚手架
- **类比边界强制** —— 每个类比必须填三列：熟悉元素 → 技术对应 → **类比在哪失效**
- **内置类比库** —— 18 条常用技术类比，每条都带失效边界（这是社区类比库普遍缺失的部分）
- **表达纪律** —— 禁用「简单来说」「显然」「众所周知」等轻慢词；一个分句一个意思；具体压过抽象
- **受众适配** —— 默认读者是"聪明的成年人，只是没有这个领域背景"；用户说明身份时用对方领域词汇当桥梁
- **教学式变体** —— 前置路径、苏格拉底式引导、理解检查（仅在用户明确想学时启用）

### 视觉层

- **按关系选视觉** —— 结构用分层图、对比用卡片、流程用流程图、状态变化用动画
- **大图少字（正确理解）** —— 说的是每节的视觉主导权，**不是全文字数上限**。一页可以写 2000 字，只要这些字在解释图里的东西
- **动效 opt-in** —— 只有运动能解释状态变化时才用；必须遵守 `prefers-reduced-motion`；必须提供 JS 关闭时也能读的静态态
- **离线自包含** —— 渲染不依赖任何远程图片、字体、CSS、库或服务

### 工程层

- **三层校验** —— 静态 / JS 语法 / 几何实测，逐层递进
- **退出码语义** —— `0` 通过、`1` 缺陷、`2` 没测（明确区分"没跑"和"通过"）
- **eval 用例** —— 4 个行为测试，覆盖机制+动效、类比边界、验证诚实、范围拒收
- **可回归的机械断言** —— 改 skill 后可验证没把已有能力改坏

## 相对来源的增强

这一节说明 ELI5++ 相比上面四个来源**具体多了什么**。

### 1. 第一原则：不许声称未验证的验证

这是最重要的差异。四个来源都要求"交付前检查"，但**没有一个解决"声称检查过、其实没检查"**。

ELI5++ 把它变成硬规则：

- 禁止说「已确认视觉效果正常」「移动端适配良好」——除非真的渲染并检查过
- 允许说「静态校验通过；未进行浏览器渲染，几何与视觉质量未验证」
- 交付必须附**验证声明**，明确写出做了什么、没做什么

`check_geometry.py` 的退出码 `2` 是这条原则的落地：**"没跑"不是"通过"**。

### 2. 第二原则：简化不能吃掉风险

来源普遍强调"通俗易懂"，但没人处理一个硬边界：**会让人做出错误决定的警告，不能被简化掉，也不能被类比软化。**

- 涉及不可逆操作、资金、健康、安全、法律后果时，警告必须先用直白语言说清，**然后**才回到图解叙述
- 不允许把「这会永久删除数据」写成「相当于把便签撕掉」——便签撕掉还能重抄，数据删了不能
- 优先级明确：**准确性 > 可读性 > 美观**，不可调换

### 3. 修掉一个真实的模板缺陷

社区实现里，动效组件常见写法是：

```css
.stage-step { opacity: .28; }                          /* 默认就暗 */
@media (prefers-reduced-motion: reduce) { .stage-step { opacity: 1; } }
```

这个写法**只给 reduced-motion 留了后路，没给"JS 被禁用"留后路**。结果是：三层脚本全部 PASS，但读者关掉 JS 后所有步骤都不可见。

ELI5++ 改为 opt-in：

```css
.stage-step { opacity: 1; }                            /* 默认可读 */
.stage--armed .stage-step { opacity: .28; }            /* 脚本启用后才变暗 */
```

并且**把这条经验固化成校验规则**：无 `<script>` 却默认变暗 → `ERROR`；有 `<script>` → `WARN`。这样同类 bug 以后会被脚本拦住。

### 4. 补上 SVG 无障碍盲区

多数 HTML 校验器对 `<svg>` 完全放行，但 SVG 恰恰是图解类产物的主要媒介。

ELI5++ 的规则：内联 `<svg>` 必须有可访问名——`<title>`、`role="img"` + `aria-label`、或显式 `aria-hidden="true"`（纯装饰时）。四种正确写法均放行，未闭合的 `<svg>` 也能抓到。

### 5. 类比库重建：18 条，全部带边界

社区里最全的类比库有 54 条，但 `grep` 下来**一条失效边界都没有**。

没有边界的类比不是资产，是负债——读者记住了一个错误模型，还以为自己懂了。

ELI5++ 重建了 18 条，每条强制三列。举几个例子：

| 概念 | 类比 | **类比在哪失效** |
|---|---|---|
| Cache | 饭盒提前装好饭 | 饭盒不会过期、不会被别人改、不会和冰箱不一致 |
| Deadlock | 两人互等 | 漏了关键点：死锁需**四条件同时成立**，打破任一即解除 |
| Race condition | 抢最后一块蛋糕 | 抢蛋糕结果是"一人得到"；竞态的真实危害是**状态被写坏** |
| Git branch | 分叉的路 | 分支只是一个指针，成本几乎为零，和"分叉路"直觉相反 |

### 6. eval 运行器不调 LLM

参考实现的 eval 运行器用 `claude -p` 调用外部 CLI，再用另一个模型打分。两个问题：换环境跑不起来；LLM 打分与作者共享盲区，证据强度弱。

ELI5++ 的版本只做**机械可判定**的断言，其余明确标为 `MANUAL`：

```
5/5 mechanical passed, 2 manual pending
```

**不要读成"5/5 通过"**——机械断言只覆盖可判定的部分。这是第一原则在工具层的应用。

### 7. 篇幅不再被"大图少字"压死

原始表述容易被读成"整体要少写字"。ELI5++ 澄清它约束的是**每节的视觉主导权**，并给出三档篇幅，默认走"标准"。

判断标准改为：**文字有没有依附于某个视觉关系**，而不是"字有多少"。

### 8. 新增自我修正协议

写作中最常见的失败不是"一开始就错"，而是**不知不觉滑回熟悉的术语**。

ELI5++ 要求：发现自己刚写的句子引入了未解释术语，**下一句立刻纠正**，不要假装没发生。这些修正是产物的一部分，不是羞于示人的痕迹。

## 安装

把 `eli5-plus-plus/` 整个目录复制到你的 Agent 的 skills 目录。

不同 Agent 的目录位置不同，常见位置：

```bash
# 通用（多数 Agent 兼容 SKILL.md 格式）
cp -R eli5-plus-plus ~/.agents/skills/

# Claude Code
cp -R eli5-plus-plus ~/.claude/skills/
```

安装后重启或开新任务，让 Agent 重新发现 skills。

**依赖**：Python 3（标准库即可）。几何实测需要 Playwright：

```bash
pip install playwright
playwright install chromium
```

不装 Playwright 也能用，但几何校验会返回 `exit 2`（未验证），交付时只能声明"仅完成静态验证"。

## 校验体系

三层，逐层递进。**每一层都在补前一层抓不到的东西。**

### Tier 1 — 静态（必做）

```bash
python3 scripts/check_html.py --strict artifact.html
```

14 条硬规则：远程运行时资源、CSS `url()` / `@import` 远程引用、`fetch`/`WebSocket`/`XMLHttpRequest`、缺失 `alt`、`role="img"` 无可访问名、**内联 SVG 无可访问名**、未替换占位符、缺 `lang`、缺 viewport、`<main>`/`<h1>` 基数。

### Tier 2 — JS 语法（产物含 `<script>` 时必做）

```bash
python3 scripts/check_js.py artifact.html
```

对每个内联块和本地 `src` 执行 `node --check`。跳过 `application/ld+json`、`importmap` 等非执行类型。

### Tier 3 — 几何实测（有 Playwright 时）

```bash
python3 scripts/check_geometry.py artifact.html
```

在 **320 / 375 / 1440px** 三档视口实测：横向滚动、元素出界、控件逃逸、外部请求、块重叠。

| 退出码 | 含义 | 该怎么报告 |
|---|---|---|
| `0` | 实测通过 | 可以声明几何已验证 |
| `1` | 发现缺陷 | 必须修，不能交付 |
| `2` | Playwright 缺失，**根本没测** | 只能声明"未进行浏览器渲染" |

**为什么三层都要**：实测过一个样本，Tier 1 全部通过，但页面里有个 1200px 宽的元素——静态分析看不见，Tier 3 一眼抓出。

## 设计原则

1. **准确性 > 可读性 > 美观** —— 这个优先级不可调换
2. **类比是脚手架，不是结论** —— 删掉类比后解释必须仍然成立
3. **不许把"部分验证"说成"验证完成"**
4. **篇幅服从深度** —— 宁可写厚，不要把机制压成口号
5. **视觉承担解释** —— 能用图讲清的关系，不靠大段正文
6. **简化不能吃掉风险** —— 会让人做错决定的警告，不许软化

## 已知局限

诚实列出，避免使用者产生错误预期：

- **表达纪律无法机械校验** —— 「禁用轻慢词」「句长」「类比边界」目前都是写给模型看的指令，没有脚本能验证。这部分质量仍依赖人读产物
- **Tier 3 依赖 Playwright** —— 不装则几何未验证。脚本会诚实报 `exit 2`，不会假装通过
- **`quick_validate` 查不出内容问题** —— 它只查结构。过时引用、规则不可执行这类问题需要人工比对
- **eval 断言是 topic-specific** —— 拿 eval 0 去评一个不相关的产物，那些断言会落到 MANUAL。它是改 skill 时的回归工具，不是通用产物评分器
- **篇幅档位是建议值** —— 不是硬性限制，实际按内容需要调整
